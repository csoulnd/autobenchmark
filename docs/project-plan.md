## 已验证DSV4场景的测试矩阵（不是全局默认值）

1K=1024 tokens；正式请求数为并发×4。

| 输入 / 输出 | 并发 | 正式请求数 | 目标前缀比例 |
|---|---:|---:|---|
| 64K / 1K | 64 | 256 | 50%、90%，分别运行 |
| 64K / 1K | 32 | 128 | 50%、90%，分别运行 |
| 128K / 2K | 32 | 128 | 50%、90%，分别运行 |

采用 prefix_num=1、seed=1、request_rate=0、P DP预热参数=2。手工基线与首次Agent执行各一轮；强弱模型复现各两轮。弱模型按执行时实际可用型号选择并记录依据，不以价格或推理档位代替能力判断。前缀比例是构造目标，实测命中率单独核验。

## 资源与异常原则

每个最小case前检查服务状态，结束更新状态；有效且配置匹配的READY服务跳过deploy/smoke，否则按状态部署并进行default冒烟。性能测试取得容器级独占锁后执行。是否复用、缓存处理、是否停止服务或容器由job_spec中的case与任务结束策略决定，不因最后一个case而自动清理。默认任务结束停止本任务服务及容器，用户有特殊需求时覆盖，不在首次对话反复询问默认策略。

job_spec的最大重试次数默认3（首次尝试之外）；重试前确认服务和残留状态，按attempt保留证据。耗尽后上报该case失败，安全条件满足时处理下一case；故障分类后续扩展。v3 已实现串行 case 调度和独立重试预算；精度、并行调度与复杂恢复后续扩展。

## 实例拓扑与双机功能验证（当前阶段）

用户确认采用分层 deployment：model/runtime/instances/connections/endpoint；case 独立，sub_tasks 显式串行组合。先保留单机 PD 并扩展到双机 PD；只做功能小负载，不将功能结果作为性能基线。phase 并行屏障与多 P/D 实例不在本轮范围。

当前实现为 Linux 协调端加固定节点脚本：节点分别预检、冻结包与启动脚本，按逻辑 node/container_group 创建容器。模型进程健康后启动 proxy，入口冒烟后才启动客户端；整套服务身份跨节点核验，失败逐节点收尾。动态端口避开宿主临时客户端端口区间，避免 SSH 与服务争用。

验收包括 Schema/引用与设备冲突检查、单机 PD 真实请求、双机 PD 真实请求、跨节点缓存重置/预热、请求完整性与输出长度、重复收尾及本任务设备释放。实际服务器地址、镜像解析值、硬件告警、执行轨迹和测量结果仅记录于仓库外任务产物。

## 2026-11-01：任务级容器复用

本节取代按 deployment/container_group 隔离容器的旧策略。每台机器的首个任务容器以总 job_id 命名，兼容镜像和容器配置跨部署复用；预检汇总模型挂载和设备，不兼容时使用子编号容器。移除用户 placement.container_group 字段。切换部署默认 stop_service，不强制 stop_container；服务确认退出后也优先清理服务并复用容器。容器归属与服务摘要分离，共享登记控制当前服务身份。任务结束默认核验停止、删除全部本任务容器，保留宿主产物、镜像和权重。
