## 已验证DSV4场景的测试矩阵（不是全局默认值）

1K=1024 tokens；正式请求数为并发×4。

| 输入 / 输出 | 并发 | 正式请求数 | 目标前缀比例 |
|---|---:|---:|---|
| 64K / 1K | 64 | 256 | 50%、90%，分别运行 |
| 64K / 1K | 32 | 128 | 50%、90%，分别运行 |
| 128K / 2K | 32 | 128 | 50%、90%，分别运行 |

采用 prefix_num=1、seed=1、request_rate=0、P DP预热参数=2。手工基线与首次Agent执行各一轮；强弱模型复现各两轮。弱模型按执行时实际可用型号选择并记录依据，不以价格或推理档位代替能力判断。前缀比例是构造目标，实测命中率单独核验。

## 资源与异常原则

每个最小case前检查服务状态，结束更新状态；有效且配置匹配的READY服务跳过deploy/smoke，否则按状态部署并进行default冒烟。性能测试取得容器级独占锁后执行。是否复用、缓存处理、是否停止服务或容器由job_spec中的case与任务结束策略决定，不因最后一个case而自动清理。当前DSV4场景明确选择最后停止服务及容器；新任务重新收集策略。

job_spec的最大重试次数默认3（首次尝试之外）；重试前确认服务和残留状态，按attempt保留证据。耗尽后上报该case失败，安全条件满足时处理下一case；故障分类后续扩展。当前单 case v2 已统一 execution.max_retries、smoke 和 cleanup 字段；跨 case 调度后续扩展。

## 仓库与本地产物边界

- `docs/`：仅存设计文档、设计决策和整体工程计划。
- `skills/`、`tests/`：可复用实现、配方、配置样例和测试，正常纳入版本管理。
- 仓库外本地产物目录（本机 `D:/autobenchmark-local/logs/`）：日志、现场证据、交接、报告与运行产物，不提交或推送；仓库内不存放本地归档。
- 原始远端运行目录保持原样；本次整理不迁移服务器文件，不修改远端Git仓库。

详细现场信息与测试测量值保存在仓库外本地产物目录，不作为远端仓库文档依赖。
