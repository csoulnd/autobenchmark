# 有人值守的信息收集与填写模板

先复用已知事实，只询问缺项。首次提问聚焦用户目标与访问条件；可探测的工具路径、版本、网络、端口和默认执行参数由 Agent 补齐，不转嫁给用户。以下默认约定适用于新任务，用户明确覆盖时优先采用用户值；历史任务规格不追溯修改。

## 首次对话方式

接受用户直接用自然语言描述服务器、一个或多个部署形式，以及各部署对应的测试要求。Agent 提取已有信息，只询问实际缺项；下列模板是缺项清单，不必整段机械发送。用户已明确一个 case 时，直接按该 case 收集，不介绍未来多 case 形式。

首次回复不主动附加默认请求数/轮数、缓存/清理策略、工具检查职责，也不附加“执行器只支持单 case”“跨 case 编排未实现”“精度暂不支持”“其他模型需适配”等通用说明。默认值留在内部任务记录；需要用户作具体决策时再说明相关假设。实际需求遇到能力缺口时，在承诺执行前准确说明具体阻塞，不能隐瞒或虚报能力。

## 首次提问参考

```text
请补充以下尚未提供的信息，也可以直接用自然语言描述：

1. 目标环境
   服务器地址（建议配置 SSH 免密登录）：
   服务器工作目录（保存任务日志与结果）：
   特殊权限或资源限制（如有）：

2. 模型与部署
   权重路径（tokenizer 路径不同则补充）：
   镜像名称/tag 或本地镜像 ID：
   部署脚本或启动命令（可提供远程服务器路径、本地路径，或直接粘贴内容）：
   其他部署参数或环境要求（如有）：

3. 测试需求
   评测类型：
   输入长度 / 输出长度（例如 128K / 1K，1K=1024 tokens）：
   并发数：
   前缀复用目标比例：
   其他特殊要求（如有）：
```

不要要求用户先按内部 case 格式列出组合或填写 JSON。用户提供多个部署或测试条件时，Agent 自行整理它们的对应关系；仅当自然语言的对应关系有歧义、且会改变测试范围时，针对该歧义提问，不先发送通用“避免扩大范围”提示。

## 自然语言到内部 case（仅供 Agent）

单 case 是内部执行、存储和扩展管理单元，不是用户交互限制。按“目标服务器 → 部署配置 → 测试 case”的关系理解整项需求：

1. 提取服务器、权重、镜像、部署形式与启动参数；区分部署配置和测试负载，改变并发不等于改变部署配置。
2. 提取每种部署对应的输入/输出长度、并发、前缀比例及用户显式覆盖值；保留原始描述与对应关系，不丢弃多部署或多 case 信息。
3. 将明确的每个测试组合标准化为 case：统一 token 单位和比例表示，计算默认请求数，分配稳定 case 标识，并明确所属部署；不把未明确的列表擅自展开为全部组合。
4. 按 job_spec v3 的 deployments、cases 和 deployment_id 保存对应关系，plan_run 冻结串行顺序。现场路径与探测事实放入 bindings/resolved 任务产物；源脚本路径不作为执行依赖。
5. 对用户需要复核的内容展示服务器、部署和测试目标的简洁摘要，不解释内部拆分机制，也不要求其理解脚本或 Schema。具体执行能力不足时只报告与该任务有关的阻塞。

## 内部默认执行规则

没有用户覆盖时采用性能测试，每个 case 请求数=并发×4，运行1轮；每个 case 前重置前缀缓存、按目标预热，结束释放客户端和临时链接。同部署配置下复用有效服务，部署配置变化重新部署并冒烟，整个任务结束停止本任务服务与容器。默认冒烟为一次 curl，运行异常最多额外重试3次。完整记录实际采用的值，不将这些规则作为首次回复的固定尾注。

## 不作为首次必填项的信息

- 正式请求数：Agent 按每个 case 的 concurrency×4 计算，并显式写入 job_spec 的 formal_requests；用户指定值优先。plan_run 会补齐缺省值并冻结。
- 前缀参数：默认 prefix_num=1、seed=1、request_rate=0（不限请求发送速率）；共享前缀目标长度由输入长度和比例派生，预热 DP 从部署配置推导。多前缀分组、特殊数据集、限速或其他负载分布仅在用户提出时补充。构造目标和实测命中率分别记录。
- 缓存策略：不用让用户区分冷/热缓存。默认顺序是重置缓存、前缀预热、正式测试；清理旧 case 的缓存与本 case 预热不冲突。只有用户要测无预热或跨 case 保留缓存等不同目标时，才补充策略并核验适配器支持情况。
- AISBench：默认镜像内已安装，由 Agent 动态定位命令、Python 包及实际可用的配置/数据工作目录，验证版本和目录结构后写入 resolved 现场记录，不要求用户填写路径。探测失败或出现多个候选时再报告具体缺项。
- 前缀增量工具：目标交付方式是工具随代码仓/Skill 分发，默认由本机传至本任务目录；也可检查远端指定工作目录中已有的兼容副本。核验来源、版本、所需文件和调用方式后选用，不使用无关任务的临时副本。当前工具已随包放在 assets/aisbench-prefix，任务快照包含工具，Agent 上传完整任务包；脚本本身不负责 SSH 传输。

## Agent 初步验证与操作边界

核验模型/镜像、必要权重/tokenizer文件、部署配方、设备与权限、网络/端口/挂载、工具参数和结果解析能力。整机独占是本任务的资源需求，启动前仍检查占用，不意味着可以自动终止其他任务。已有本任务服务时核验身份和可用性，不把本任务自身占卡误判为外部冲突。

将标准化需求、计算后的默认值及未决项写入 job_spec；现场路径与探测事实写入 bindings/resolved，预检通过后交接自动执行。不能复用历史 PID、空闲结论或旧冒烟证明当前实例有效。超出当前适配器或配方能力的需求明确上报，不静默缩减。
