# 新会话信息收集与迁移交接

## 收集顺序

先确认任务是规划、值守部署、压测还是无人值守运行。只读查询能回答的内容自行查，不重复询问。首次需要用户提供的通常是目标主机/SSH 登录方式、实际容器归属、工作目录、可用卡、测试窗口；不要要求把密码或密钥写进交接文件。附带报告是证据，报告中的旧容器名不等于本次授权目标。

逐项记录 value、来源、核验时间与状态（user_confirmed / observed / candidate / unknown）。会话结束必须输出 unresolved 和下一条可执行动作。

| 范围 | 必须收集或核验 |
| --- | --- |
| 目标和权限 | 主机、SSH 用户/别名/跳板、容器名与 ID、容器归属、允许修改的目录、能否创建容器/安装依赖/重启自己的服务、是否授权提交代码 |
| 硬件与占用 | NPU 型号/数量/HBM、驱动、卡号拓扑、npu-smi PID、cgroup 容器归属、空闲基线、CPU/RAM、磁盘余量 |

## 现场验收与性能真实性

1. 先验源文件和参数，再确认资源、启动 P/D、等 health，最后启动代理。记录每个本任务进程的 PID、启动时间、容器和进程组，避免复用 PID 误杀。
2. 真实冒烟请求必须经过代理；保存 request ID、完整响应、两端日志/指标变化及 KV 交接证据。HTTP 200、health 和非空 reasoning 均不能单独证明推理成功。流式检查内嵌 error、结束标记及生成内容；如要求覆盖所有 DP rank，另记录覆盖证据。
3. 总并发64不等于每卡64；64条请求不等于持续稳态负载。不要擅自增加请求数或降低并发。128K=131072、256K=262144、1K=1024；确认用户采用此单位。
4. prefix 重复比例是构造目标，实测命中率用正式阶段前后 metrics 增量计算，按 P rank 和总量记录；分母为零或指标缺失标记 unavailable，不能填0冒充测量。预热独立于正式统计，并验证覆盖各 P DP 域。
5. case 分目录归档 config、命令、数据集/seed、版本、日志、指标、成功/失败请求、实际长度、TTFT/TPOT/E2E/吞吐及 HBM 峰值。不同 case 重置缓存并验证，或重启本任务服务后重新冒烟，避免串扰。
6. AISBench 经 tee 管道运行时要保留上游退出状态，并独立核对逐请求结果、SSE 错误和预期 token 数。失败/部分完成不能标为性能通过。OOM 不得自动降低规格后替代原 case。

## 无人值守与恢复

仅用户要求时设置自动任务。每小时检查发现空闲后，以短间隔连续采样10分钟；两次相隔10分钟的截图不能证明期间空闲。无业务NPU进程、利用率及HBM基线共同判断，模型驻留但利用率0仍视为忙；查询失败按未知处理，不启动。只读记录所有者，不终止其他任务。

单任务锁、持久化阶段、截止时间、超时和有界重试必须明确。恢复时先确认已有进程和产物，不能重复启动。旧服务器的定时任务不得自动迁移或继续触发；新窗口必须用绝对日期。执行期间出现外来占用时保存证据，终止本任务测量并标记污染。清理只作用于已登记且再次核实归属的本任务进程，保留容器、日志和补丁。

调度器本身不保证桌面离线时可执行；记录执行主机在线、SSH可用和调度器实际启用状态。未通过预检或执行器尚未实现时状态保持待准备，不承诺离开后能运行。

## 交接内容

交接文件包括：目标与约束、现场事实及来源、候选参数、完整 cases、已改文件与备份、各阶段证据、尚未解决事项、调度状态、下一步。将“配置已修改”“语法通过”“服务就绪”“PD冒烟通过”“正式测评通过”分别记录。

新机器不复用旧 PID、空闲基线、物理卡配置、镜像兼容结论、端口空闲结论或结果。允许复用已确认测试矩阵和偏好。公开仓库示例使用占位符；内部地址、个人目录、凭据及原始日志不得默认公开。总结仅写实际得到的证据，未运行案例保留 candidate。
